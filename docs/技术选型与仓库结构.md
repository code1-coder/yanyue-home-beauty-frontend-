# 技术选型与仓库结构

> 本文只说明当前工程规划，不修改[原始 PRD](服务产品需求文档（PRD）.md)的产品功能、支付渠道、兼容要求和 P0/P1/P2 优先级，也不修改[原始原型](原型整体结构.md)的页面结构、建议路由及阶段划分。两份原始资料为产品基准；技术实现与产品范围出现差异时，记录待确认事项，不自行裁剪需求。

## 三端技术方向

| 端 | 当前规划的工程形态 | 框架与组件库 | 产品依据 |
| --- | --- | --- | --- |
| 消费者端 | 独立微信小程序工程 | HBuilderX + uni-app Vue 3 + uview-plus | [消费者需求](consumer/需求.md)、[消费者原型](consumer/原型.md) |
| 服务者端 | 独立微信小程序工程 | HBuilderX + uni-app Vue 3 + uview-plus | [服务者需求](provider/需求.md)、[服务者原型](provider/原型.md) |
| 管理后台 | 独立 Web 工程 | Vue 3 + Element Plus | [后台需求](admin/需求.md)、[后台原型](admin/原型.md) |

这是 Vue 3 对应组件库的实施方向，不将原始文档中的 uView/Element UI 组件示意机械地当作新版 API。具体依赖版本、构建方式及组件兼容性在获得工程初始化授权后验证并由工程清单与锁文件固定；后端框架、正式接口契约和支付接入方案尚未确定。本仓目前只有文档，不含可运行工程。

## 范围差异与待确认

当前优先规划微信小程序工程，不建立 Android/iOS 工程；这只是工程实施顺序，**不取消原始 PRD 的 iOS/Android 兼容要求**。原始 PRD 的**微信/支付宝支付均为 P0**，原型确认订单页也列出两种支付方式；当前小程序平台与原始支付、兼容范围如何配合，须产品与技术负责人确认交付阶段和实现方案。在确认前，拆分需求、原型和接口能力清单保留原始渠道与优先级，不宣称某渠道已经接入或被排除。

接口路径、字段、鉴权、订单与支付状态最终权威判定、跨平台适配及提审流程均待设计；不得以某端 UI、技术路线或此目录结构替代原始业务规则及正式接口契约。
