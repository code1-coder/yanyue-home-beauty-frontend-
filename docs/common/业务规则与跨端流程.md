# 共通业务规则与跨端流程

> 本文为两份原始文档的共通章节摘录。端内需求和原型分别见 [消费者端](../consumer/需求.md)、[服务者端](../provider/需求.md)、[管理后台](../admin/需求.md)。如摘录与原始文档不一致，以原始文档为准。

## 1. 项目背景与目标

### 1.1 项目背景
随着上门服务消费习惯的成熟，美容服务逐渐从到店向上门场景延伸。平台采用自营模式，整合个人/个体工商户美容师资源，为用户提供上门美容服务。平台统一收款、统一结算、统一管控，解决用户信任、服务标准化、美容师收益结算等问题。

### 1.2 产品目标
- 为用户提供“找美容师 → 选项目 → 约时间 → 上门服务 → 评价”的完整闭环。
- 为美容师提供入驻、排班、接单、收益、提现、工具采购的一体化工作台。
- 为平台管理者提供审核、订单、财务、抽成、内容、数据等管控能力。
- 实现担保交易、平台抽成、自动结算、提现审核的财务闭环。

### 1.3 成功指标（MVP）
- 用户下单转化率、订单完成率、复购率。
- 美容师入驻审核通过率、接单率、完单率。
- 平台 GMV、抽成收入、结算准确率。
- 投诉率、退款率、评价评分。

## 2. 产品定位与业务模式

### 2.1 业务模式
| 项目           | 说明                                                   |
| -------------- | ------------------------------------------------------ |
| 平台模式       | 自营平台，美容师为个人/个体工商户合作方                |
| 交易方式       | 担保交易，用户支付到平台，服务完成后按周期结算给美容师 |
| 抽成方式       | 默认抽成模板 + 独立抽成，订单创建时快照抽成比例        |
| 抽成基数       | 订单实付金额（含项目实付 + 上门费 - 优惠分摊）         |
| 结算周期       | 可配置，默认 T+7                                       |
| 提现规则       | 余额 > 1 元可提，手续费可配置                          |
| 服务范围       | 按距离展示，平台不强制拦截超区订单，美容师可拒单       |
| 上门费         | 由美容师设置，参与平台抽成                             |
| 缓冲时间       | 美容师自设前缓冲、后缓冲                               |
| 工具商城       | 平台自营商品，独立订单，不与服务订单关联               |
| 即时通讯       | 暂不提供，使用电话、站内消息、短信通知                 |
| 资质要求       | 实名认证、健康证、美容师证                             |
| 发票/保险/税务 | 暂不处理                                               |

### 2.2 角色定义
| 角色             | 终端     | 核心诉求                                 |
| ---------------- | -------- | ---------------------------------------- |
| 消费者           | 移动端A  | 找美容师、选项目、预约、支付、评价       |
| 服务者（美容师） | 服务者端 | 入驻、排班、接单、收益、提现、购买工具   |
| 管理者           | 管理后台 | 审核、订单管控、财务结算、内容与系统管理 |

## 3. 核心业务流程

### 3.1 消费者下单流程
```
定位 → 浏览项目/美容师 → 选择美容师与项目 → 选择半小时时段
→ 选择地址 → 计算上门费 → 确认订单 → 支付
→ 美容师接单 → 上门服务 → 完成服务 → 用户评价 → 平台结算
```

### 3.2 美容师入驻流程
```
注册登录 → 实名认证 → 上传健康证、美容师证 → 提交审核
→ 平台审核 → 通过/驳回 → 设置服务范围、项目、排班 → 开始接单
```

### 3.3 提现流程
```
订单完成 → 进入待结算 → 结算周期到期 → 转为可提现
→ 美容师申请提现 → 平台审核 → 打款 → 到账记录
```

### 3.4 工具购买流程
```
浏览商品 → 下单 → 支付 → 发货 → 收货 → 售后
```

### 3.5 管理审核流程
```
提交资料 → 审核中心 → 审核通过/驳回 → 通知用户 → 重新提交或生效
```

## 4. 业务规则与约束

### 4.1 抽成与结算规则
| 规则项     | 规则                                                       |
| ---------- | ---------------------------------------------------------- |
| 抽成模板   | 平台可设置默认抽成模板，可按城市、项目分类、美容师等级配置 |
| 独立抽成   | 可针对特定美容师设置独立抽成比例，优先级高于默认模板       |
| 抽成快照   | 订单创建时快照抽成比例，后续修改不影响历史订单             |
| 抽成基数   | 订单实付金额 = 项目实付 + 上门费 - 优惠分摊                |
| 平台抽成   | 订单实付金额 × 抽成比例                                    |
| 美容师收入 | 订单实付金额 - 平台抽成                                    |
| 结算周期   | 可配置，默认 T+7                                           |
| 退款冲正   | 发生退款时，按退款金额比例冲正平台抽成与美容师收入         |

### 4.2 排班与预约规则
| 规则项    | 规则                             |
| --------- | -------------------------------- |
| 排班粒度  | 半小时为一段                     |
| 服务时长  | 不固定，由项目自定义             |
| 缓冲时间  | 美容师自设前缓冲、后缓冲         |
| 订单占用  | 前缓冲 + 服务时长 + 后缓冲       |
| 冲突检测  | 系统自动检测，已占用时段不可预约 |
| 请假/暂停 | 美容师可设置请假、暂停接单       |

### 4.3 服务范围与上门费
| 规则项     | 规则                                 |
| ---------- | ------------------------------------ |
| 服务半径   | 美容师设置，平台不强制限制           |
| 超区处理   | 平台不介入，用户可下单，美容师可拒单 |
| 上门费     | 美容师设置，支持固定、阶梯、满免     |
| 上门费抽成 | 参与平台抽成                         |

### 4.4 提现规则
| 规则项     | 规则                             |
| ---------- | -------------------------------- |
| 提现门槛   | 余额 > 1 元                      |
| 提现手续费 | 可配置固定金额、比例、最低手续费 |
| 到账金额   | 提现金额 - 提现手续费            |
| 提现审核   | 平台审核后打款                   |

### 4.5 资质与审核
| 规则项   | 规则                             |
| -------- | -------------------------------- |
| 资质要求 | 实名、健康证、美容师证           |
| 审核方式 | 平台人工审核                     |
| 到期提醒 | 资质到期前提醒，过期自动暂停接单 |

### 4.6 工具商城
| 规则项       | 规则     |
| ------------ | -------- |
| 商品来源     | 平台自营 |
| 关联服务订单 | 不关联   |
| 影响接单资格 | 暂不影响 |
| 影响等级     | 暂不影响 |

## 6. 状态机

### 6.1 订单状态
```
待支付 → 已支付/待接单 → 已接单/待服务 → 服务中 → 已完成 → 已结算
分支：已取消、退款中、已退款、售后中
```

### 6.2 美容师审核状态
```
待提交 → 待审核 → 通过 → 驳回 → 禁用
```

### 6.3 提现状态
```
申请中 → 审核通过 → 打款中 → 已到账 → 驳回
```

### 6.4 结算状态
```
待结算 → 可提现 → 提现中 → 已提现
```

# 五、关键页面流转

## 1. 消费者下单
```
首页 → 项目详情 → 预约页 → 选时段 → 选地址 → 确认订单
→ 支付 → 支付结果 → 订单详情 → 评价
```

## 2. 美容师接单
```
工作台（新订单提醒）→ 订单详情 → 接单
→ 开始服务 → 完成服务 → 上传凭证 → 订单完成
```

## 3. 美容师入驻
```
登录 → 入驻申请 → 提交 → 审核状态（待审核）
→ 通过 → 设置排班/项目/服务范围 → 工作台
```

## 4. 提现
```
收益中心 → 提现 → 输入金额 → 手续费展示 → 提交
→ 管理后台提现审核 → 打款 → 到账记录
```

## 5. 管理审核
```
审核中心 → 选择类型 → 查看详情 → 通过/驳回 → 通知用户
```

# 七、落地建议

1. **uni-app 页面结构**：按 `pages/消费者`、`pages/服务者` 分包，或做成两个独立 App/小程序，避免包体过大。
2. **uView 组件对应**：`u-swiper`、`u-grid`、`u-calendar`、`u-popup`、`u-form`、`u-upload`、`u-tabs`、`u-empty`、`u-toast`。
3. **Element UI 组件对应**：`el-table`、`el-dialog`、`el-form`、`el-tabs`、`el-descriptions`、`el-timeline`、`el-calendar`、`el-upload`、`echarts`。
4. **原型工具**：可用 Axure / 墨刀 / Figma 先出低保真，确认页面流转后再进入高保真。
5. **建议先确认**：优惠分摊规则、退款抽成冲正规则、美容师拒单是否影响排序。这三项会影响订单和财务页面的字段设计。
