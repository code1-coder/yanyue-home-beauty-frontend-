# 后端接口契约规范

## 1. URL 路径前缀

### 1.1 三端路径约定

| 端 | 路径前缀 | 说明 | 鉴权方式 |
|---|---------|------|---------|
| **消费者端** | `/app-api/beauty/customer/` | 消费者 C 端 App/H5 | JWT（会员令牌） |
| **服务者端** | `/app-api/beauty/provider/` | 服务者 B 端 App | JWT（会员令牌 + 服务者身份） |
| **管理后台** | `/admin-api/beauty/` | 管理员 PC 后台 | JWT（管理员令牌） |

### 1.2 路径命名规范

- 使用小写字母 + 连字符（kebab-case），例如 `service-order`、`provider-project`
- RESTful 风格：
  - `GET /resource` - 列表
  - `GET /resource/{id}` - 详情
  - `POST /resource` - 创建
  - `PUT /resource` - 更新
  - `DELETE /resource/{id}` - 删除
- 非资源操作使用动词：
  - `POST /service-order/accept` - 接单
  - `POST /service-order/reject` - 拒单
  - `POST /withdraw/apply` - 申请提现

## 2. 请求与响应格式

### 2.1 统一响应结构

沿用 RuoYi-Vue-Pro 的 `CommonResult<T>` 规范：

**成功响应**：
```json
{
  "code": 0,
  "data": { ... },
  "msg": "操作成功"
}
```

**失败响应**：
```json
{
  "code": 500,
  "data": null,
  "msg": "错误信息"
}
```

**分页响应**：
```json
{
  "code": 0,
  "data": {
    "total": 100,
    "list": [ ... ]
  },
  "msg": "操作成功"
}
```

### 2.2 分页参数

**请求参数**（沿用现有规范）：
- `pageNo`：页码，从 1 开始
- `pageSize`：每页条数，默认 10，最大 100

**响应字段**：
- `total`：总记录数
- `list`：当前页数据

### 2.3 时间格式

- **请求与响应统一使用时间戳**（毫秒，Long 类型）
- 示例：`1704067200000`（2024-01-01 00:00:00）
- 前端负责时区转换和格式化显示

**特殊场景**：
- 日期选择（年月日）：使用 `yyyy-MM-dd` 字符串，例如 `"2024-01-01"`
- 时间段：使用半小时段索引（整数），例如 `0`（00:00-00:30）、`1`（00:30-01:00）

## 3. 错误码设计

### 3.1 错误码段划分

| 模块 | 错误码范围 | 说明 |

| **美业服务** | `1-020-000-000` ~ `1-020-999-999` | beauty 模块专用 |

### 3.2 美业模块错误码细分

| 子模块 | 错误码范围 | 示例 |
|-------|-----------|------|

| **项目** | `1-020-002-000` ~ `1-020-002-999` | 平台项目、服务者项目关联 |

## 4. 鉴权与权限

### 4.1 消费者端鉴权

- **登录方式**：复用 `yudao-module-member` 的会员登录
  - 手机号 + 短信验证码
  - 微信授权登录
- **令牌传递**：`Authorization: Bearer {token}`
- **权限校验**：
  - 所有接口强制登录
  - 查询只能查自己的订单、地址、评价
  - 不能访问其他消费者数据

### 4.2 服务者端鉴权

- **登录方式**：复用 `yudao-module-member` 的会员登录
  - 手机号 + 短信验证码
- **双重身份校验**：
  1. 验证会员登录（JWT 令牌）
  2. 验证当前会员关联的 `beauty_provider` 存在且审核通过
- **权限校验**：
  - 只能查询和操作自己的服务者档案、项目、排班、订单、收益
  - 接单前必须校验：审核通过 + 资质有效 + 接单开关开启

### 4.3 管理后台鉴权

- **登录方式**：复用 `yudao-module-system` 的管理员登录
- **令牌传递**：`Authorization: Bearer {token}`、`tenant-id: {tenantId}`
- **权限校验**：
  - **菜单权限**：通过 `system_menu` 表配置
  - **按钮权限**：使用 `@PreAuthorize("@ss.hasPermission('beauty:provider:create')")`
  - **数据权限**：使用 `DataScope` 按城市、区域、部门过滤

## 5. 幂等与防重

### 5.1 幂等键机制

**适用场景**：
- 接单/拒单
- 申请提现
- 支付回调
- 退款申请

**实现方式**：
- 请求头携带：`X-Idempotent-Key: {uuid}`
- 客户端生成唯一 UUID
- 服务端 Redis 存储：`beauty:idempotent:{key}` TTL 60s
- 重复请求返回首次结果

### 5.2 状态条件更新

**关键操作必须使用状态条件**：
```sql
UPDATE beauty_service_order 
SET status = '已接单', accept_time = NOW()
WHERE id = ? AND status = '待接单'
```

**影响行数为 0 则操作失败**，避免并发覆盖。

### 5.3 分布式锁

**适用场景**：
- 排班锁定
- 接单操作
- 提现申请

**实现方式**：
- 使用 Redisson 分布式锁
- 锁键示例：
  - `beauty:order:accept:{orderId}`
  - `beauty:schedule:lock:{providerId}:{date}`
  - `beauty:withdraw:provider:{providerId}`

## 6. 文件上传

### 6.1 上传接口

复用 `yudao-module-infra` 的文件上传能力：
- 上传接口：`POST /infra/file/upload`
- 返回：文件访问 URL

### 6.2 文件类型与大小限制

| 场景 | 允许格式 | 单文件大小 | 数量限制 |
|-----|---------|-----------|---------|
| **服务者头像** | jpg, png | 2MB | 1 |
| **资质证件** | jpg, png, pdf | 5MB | 每项 3 张 |
| **服务证据照片** | jpg, png | 5MB | 服务前后各 3 张 |
| **评价图片** | jpg, png | 3MB | 最多 9 张 |

### 6.3 访问控制

**敏感文件不能公开访问**：
- 服务者资质证件
- 服务证据照片（服务前后对比）
- 争议证据

**实现方式**：
- 文件 URL 携带签名或临时令牌
- 后端校验当前用户是否有权访问该文件
- 或使用对象存储的私有桶 + 预签名 URL

## 7. 数据脱敏

### 7.1 脱敏规则

| 字段 | 脱敏规则 | 示例 |
|-----|---------|------|
| **手机号** | 中间 4 位 * | 138****5678 |
| **身份证号** | 中间 10 位 * | 110101**********19 |
| **真实姓名** | 姓 + * | 张* |
| **详细地址** | 仅展示到区/县 | 北京市朝阳区*** |

### 7.2 脱敏场景

- **消费者查看服务者**：手机号脱敏
- **服务者接单前**：客户手机号脱敏，接单后完整展示
- **管理后台**：根据权限决定是否脱敏

## 8. 接口版本管理

### 8.1 版本策略

**首期不引入版本号**，待 API 稳定后再考虑：
- 路径版本：`/app-api/v2/beauty/customer/`
- 请求头版本：`API-Version: 2.0`

### 8.2 字段新增与废弃

- **新增字段**：直接加入响应，前端忽略未知字段
- **废弃字段**：
  - 保留 3 个版本周期
  - 响应中标注 `@Deprecated`
  - 文档标注 `[已废弃，请使用 xxx]`

## 9. 性能与缓存

### 9.1 缓存策略

| 数据类型 | 缓存方式 | TTL | 失效时机 |
|---------|---------|-----|---------|
| **平台项目列表** | Redis | 10 分钟 | 项目上下架/编辑后主动清除 |
| **服务者档案** | Redis | 5 分钟 | 档案更新后清除 |
| **抽成模板** | Redis | 30 分钟 | 模板变更后清除 |
| **服务者项目关联** | 不缓存 | - | 实时校验价格和启用状态 |
| **排班可用性** | 不缓存 | - | 实时查询冲突 |

### 9.2 查询优化

- **分页查询必须带索引字段**：订单查询按 `customer_user_id` 或 `provider_id` + 时间范围
- **避免深分页**：禁止跳转到超过 1000 页
- **大数据导出**：异步任务 + 文件下载

## 10. 日志与审计

### 10.1 操作日志

**必须记录的操作**：
- 服务者入驻审核（通过/驳回）
- 资质审核
- 订单改派
- 抽成配置变更
- 提现审核
- 退款操作

**日志字段**：
- 操作人（用户 ID + 用户类型）
- 操作时间
- 操作类型
- 操作前状态
- 操作后状态
- 备注

### 10.2 敏感操作审计

**接入 `yudao-module-system` 的操作日志**：
- 使用 `@OperateLog` 注解
- 记录请求参数、响应结果、异常信息
- 支持按模块、操作人、时间范围查询

## 11. 异常处理

### 11.1 异常分类

| 异常类型 | HTTP 状态码 | 处理方式 |
|---------|------------|---------|
| **业务异常** | 200 | `code != 0`，返回业务错误码 |
| **参数校验失败** | 200 | `code = 400`，返回校验消息 |
| **未登录** | 401 | 前端跳转登录页 |
| **无权限** | 403 | 提示无权限 |
| **资源不存在** | 200 | `code = 404`，返回"资源不存在" |
| **系统异常** | 500 | 返回通用错误，详细信息记录日志 |

### 11.2 异常响应示例

```json
{
  "code": 1020001002,
  "data": null,
  "msg": "服务者未审核通过，无法接单"
}
```
