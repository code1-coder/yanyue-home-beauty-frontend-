# 第三方接入方案

## 1. 概述

`yudao-module-beauty` 作为新增的美容服务业务模块，不重复造轮，复用 RuoYi-Vue-Pro 现有模块的成熟能力：

| 现有模块 | 复用能力 | 接入方式 |
|---------|---------|---------|
| **yudao-module-member** | 会员登录、资料、地址 | API 调用 + 共享会员 ID |
| **yudao-module-pay** | 支付单、退款、回调 | API 调用 + 事件监听 |
| **yudao-module-infra** | 文件上传、配置、定时任务 | API 调用 + 配置读取 |
| **yudao-module-system** | RBAC、消息、短信、审计 | 权限注解 + API 调用 |
| **yudao-module-bpm** | 审批流（可选） | BPM 流程定义 + 任务监听 |

**关键原则**：
- beauty 模块**依赖**上述模块，但上述模块**不感知** beauty 的业务逻辑
- 通过 API 调用、事件监听、配置读取实现松耦合
- 避免直接修改现有模块的表结构或核心逻辑

## 2. 接入 yudao-module-member

### 2.1 会员身份关联

**数据模型**：
- 消费者：直接使用 `member_user` 表，通过 `member_user_id` 关联
- 服务者：`beauty_provider` 表通过 `member_user_id` 关联到 `member_user`

**关联逻辑**：
```java
// 服务者入驻时创建或关联会员
MemberUserRespDTO memberUser = memberUserApi.getUser(mobile);
if (memberUser == null) {
    // 会员不存在，先创建会员账号
    Long memberUserId = memberUserApi.createUser(new MemberUserCreateReqDTO()
        .setMobile(mobile)
        .setNickname(realName)
        .setPassword(randomPassword));
    provider.setMemberUserId(memberUserId);
} else {
    // 会员已存在，直接关联
    provider.setMemberUserId(memberUser.getId());
}
```

### 2.2 登录与鉴权

**消费者端登录**：
- 复用 `MemberAuthController` 的登录接口
- 登录成功后获得 JWT 令牌
- beauty 模块通过 `SecurityFrameworkUtils.getLoginUserId()` 获取当前会员 ID

**服务者端登录**：
- 同样使用会员登录
- 登录后额外校验是否关联 `beauty_provider` 且审核通过
- 服务者端接口统一通过拦截器或 AOP 校验服务者身份

```java
@Component
public class ProviderAuthInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, 
                             HttpServletResponse response, 
                             Object handler) {
        Long memberUserId = SecurityFrameworkUtils.getLoginUserId();
        BeautyProviderDO provider = providerService.getProviderByMemberUserId(memberUserId);
        
        if (provider == null) {
            throw exception(PROVIDER_NOT_EXISTS);
        }
        if (!ReviewStatusEnum.APPROVED.equals(provider.getReviewStatus())) {
            throw exception(PROVIDER_NOT_APPROVED);
        }
        
        // 将 providerId 存入 ThreadLocal 供后续使用
        ProviderContextHolder.setProviderId(provider.getId());
        return true;
    }
}
```

### 2.3 地址管理

**复用 member 模块的地址能力**：
- 消费者下单时选择 `member_area` 中的地址
- beauty 模块调用 `MemberAreaApi.getArea(areaId)` 获取地址详情
- 订单保存地址快照（详细地址、经纬度）

```java
MemberAreaRespDTO area = memberAreaApi.getArea(reqVO.getAreaId());
if (area == null || !area.getUserId().equals(getLoginUserId())) {
    throw exception(AREA_NOT_EXISTS);
}
order.setServiceAddress(area.getDetailAddress());
order.setServiceLat(area.getLatitude());
order.setServiceLng(area.getLongitude());
```

### 2.4 会员资料

**服务者端可读取会员基础资料**：
- 头像、昵称
- 不能直接修改会员密码、手机号（需通过 member 模块接口）

## 3. 接入 yudao-module-pay

### 3.1 支付单创建

**服务订单支付流程**：
1. 消费者提交订单，beauty 模块创建 `beauty_service_order`，状态为 `待支付`
2. 调用 `PayOrderApi.createOrder()` 创建支付单
3. 返回支付单 ID 和支付参数给前端
4. 前端调起支付（微信/支付宝）
5. 支付成功后回调 beauty 模块

```java
// 创建支付单
PayOrderCreateReqDTO payOrderCreateReq = new PayOrderCreateReqDTO()
    .setAppId(payAppId) // 支付应用 ID
    .setMerchantOrderId(order.getOrderNo()) // 商户订单号
    .setSubject("上门美容服务-" + order.getProjectName())
    .setBody(order.getProjectName())
    .setPrice(order.getPayPrice()) // 支付金额（分）
    .setExpireTime(LocalDateTime.now().plusMinutes(30)) // 30 分钟过期
    .setUserIp(ServletUtils.getClientIP());

Long payOrderId = payOrderApi.createOrder(getLoginUserId(), payOrderCreateReq);
order.setPayOrderId(payOrderId);
```

### 3.2 支付回调处理

**监听支付成功事件**：
- pay 模块支付成功后发送 `PayOrderSuccessEvent`
- beauty 模块监听该事件，更新订单状态

```java
@Component
public class PayOrderSuccessListener {
    
    @Async
    @EventListener
    public void onPayOrderSuccess(PayOrderSuccessEvent event) {
        // 根据商户订单号查询服务订单
        BeautyServiceOrderDO order = orderService.getOrderByOrderNo(event.getMerchantOrderId());
        if (order == null) {
            return; // 不是美容服务订单，忽略
        }
        
        // 更新订单状态为"待接单"
        orderService.handlePaySuccess(order.getId(), event.getPayOrderId(), event.getPayTime());
    }
}
```

**幂等保障**：
- 支付回调可能重复触发
- `handlePaySuccess()` 内部使用状态条件更新：
  ```sql
  UPDATE beauty_service_order 
  SET status = '待接单', pay_time = ?, pay_order_id = ?
  WHERE id = ? AND status = '待支付'
  ```
- 影响行数为 0 则说明已处理过，直接返回成功

### 3.3 退款处理

**服务订单退款流程**：
1. 消费者或管理员发起退款申请
2. beauty 模块调用 `PayRefundApi.createRefund()` 创建退款单
3. 退款成功后监听 `PayRefundSuccessEvent`
4. 更新订单退款状态，冲正抽成和服务者收入

```java
// 创建退款单
PayRefundCreateReqDTO refundReq = new PayRefundCreateReqDTO()
    .setAppId(payAppId)
    .setMerchantOrderId(order.getOrderNo())
    .setMerchantRefundId(refundNo) // 退款单号
    .setReason(refundReason)
    .setPrice(refundAmount); // 退款金额（分）

Long refundId = payRefundApi.createRefund(refundReq);
```

**退款回调监听**：
```java
@EventListener
public void onPayRefundSuccess(PayRefundSuccessEvent event) {
    BeautyServiceOrderDO order = orderService.getOrderByOrderNo(event.getMerchantOrderId());
    if (order == null) {
        return;
    }
    
    // 更新订单退款状态
    orderService.handleRefundSuccess(order.getId(), event.getRefundId(), event.getRefundAmount());
    
    // 冲正抽成和服务者收入
    settlementService.reverseSettlement(order.getId(), event.getRefundAmount());
}
```

### 3.4 支付通道配置

**复用 pay 模块的支付通道**：
- 微信支付
- 支付宝支付
- 模拟支付（测试环境）

**支付应用 ID（appId）配置**：
- 管理后台配置专用支付应用
- beauty 模块从配置中心读取 `beauty.pay.app-id`

## 4. 接入 yudao-module-infra

### 4.1 文件上传

**复用 infra 的文件上传能力**：
- 上传接口：`POST /infra/file/upload`
- 返回文件访问 URL

**beauty 模块使用场景**：
- 服务者头像
- 资质证件图片
- 服务前后照片
- 评价图片

**访问控制**：
- 敏感文件（资质证件、服务证据）需要访问权限校验
- 可选方案：
  1. 使用对象存储私有桶 + 预签名 URL
  2. 通过 beauty 模块代理访问，校验权限后返回文件流

```java
@GetMapping("/qualification/download")
public void downloadQualification(@RequestParam("fileId") Long fileId, 
                                   HttpServletResponse response) {
    // 校验当前用户是否有权访问该资质文件
    BeautyProviderQualificationDO qualification = qualificationService.getById(fileId);
    if (!hasPermission(qualification)) {
        throw exception(ACCESS_DENIED);
    }
    
    // 从对象存储获取文件流
    InputStream fileStream = fileService.getFileStream(qualification.getFileUrl());
    // 输出到响应
    IOUtils.copy(fileStream, response.getOutputStream());
}
```

### 4.2 系统配置

**复用 infra 的配置中心**：
- 配置项存储在 `infra_config` 表
- beauty 模块通过 `ConfigApi.getConfigValue()` 读取配置

**beauty 模块配置项示例**：
| 配置键 | 说明 | 示例值 |
|-------|------|--------|
| `beauty.settlement.cycle` | 结算周期（天） | 7 |
| `beauty.withdraw.min-amount` | 最低提现金额（分） | 100 |
| `beauty.order.accept-timeout` | 接单超时时间（分钟） | 15 |
| `beauty.pay.app-id` | 支付应用 ID | 123 |

```java
// 读取配置
Integer settlementCycle = configApi.getConfigValueAsInteger("beauty.settlement.cycle");
if (settlementCycle == null) {
    settlementCycle = 7; // 默认值
}
```

### 4.3 定时任务

**复用 infra 的 Quartz 定时任务**：
- 任务配置存储在 `infra_job` 表
- beauty 模块创建自己的 Job 类

**beauty 模块定时任务示例**：

| 任务名称 | Cron 表达式 | 说明 |
|---------|-----------|------|
| `OrderExpireJob` | `0 */5 * * * ?` | 每 5 分钟检查待接单超时订单 |
| `QualificationExpireJob` | `0 0 2 * * ?` | 每天凌晨 2 点检查资质过期 |
| `SettlementReleaseJob` | `0 0 3 * * ?` | 每天凌晨 3 点释放 T+7 结算 |
| `ScheduleCleanJob` | `0 0 4 * * ?` | 每天凌晨 4 点清理过期排班 |

```java
@Component
public class OrderExpireJob implements JobHandler {
    
    @Override
    public String execute(String param) throws Exception {
        // 查询待接单超时订单
        List<BeautyServiceOrderDO> expiredOrders = orderService.getExpiredOrders();
        
        for (BeautyServiceOrderDO order : expiredOrders) {
            // 自动取消并退款
            orderService.cancelOrderByTimeout(order.getId());
        }
        
        return "处理了 " + expiredOrders.size() + " 个超时订单";
    }
}
```

## 5. 接入 yudao-module-system

### 5.1 RBAC 权限

**管理后台权限控制**：
- 菜单权限：在 `system_menu` 表配置美业菜单树
- 按钮权限：使用 `@PreAuthorize` 注解

```java
@PostMapping("/approve")
@Operation(summary = "审核通过服务者入驻")
@PreAuthorize("@ss.hasPermission('beauty:audit:provider')")
public CommonResult<Boolean> approveProvider(@RequestParam("id") Long id) {
    providerService.approveProvider(id);
    return success(true);
}
```

**权限标识设计**（已在接口契约规范中定义）：
- `beauty:audit:provider` - 审核服务者
- `beauty:provider:query` - 查询服务者
- `beauty:order:reassign` - 改派订单
- 等等...

### 5.2 数据权限

**场景**：城市/区域运营只能看负责区域的服务者和订单

**实现方式**：
- 使用 `@DataPermission` 注解
- 后端根据当前管理员的角色和数据权限范围过滤查询结果

```java
@GetMapping("/page")
@PreAuthorize("@ss.hasPermission('beauty:provider:query')")
@DataPermission(deptAlias = "p", userAlias = "p")
public CommonResult<PageResult<ProviderRespVO>> getProviderPage(
    @Validated ProviderPageReqVO reqVO) {
    // DataScope 会自动在 SQL 中加入部门或用户过滤条件
    PageResult<BeautyProviderDO> pageResult = providerService.getProviderPage(reqVO);
    return success(buildProviderRespVOList(pageResult.getList()));
}
```

## 6. 接入 yudao-module-bpm（可选）

### 6.1 适用场景

**推荐接入 BPM 的场景**：
- 服务者入驻审核（多级审批）
- 资质审核（初审 + 复审）
- 提现审核（财务审核 + 打款确认）
- 退款争议（客服 + 仲裁）

**不建议接入 BPM 的场景**：
- 服务订单的实时履约状态（接单/到达/开始/完成）
- 排班和预约

### 6.2 流程定义

**示例：服务者入驻审核流程**

```xml
<process id="beauty_provider_review" name="服务者入驻审核">
  <startEvent id="start"/>
  <userTask id="initialReview" name="初审" assignee="${initialReviewer}"/>
  <exclusiveGateway id="gateway1"/>
  <userTask id="finalReview" name="复审" assignee="${finalReviewer}"/>
  <endEvent id="approved" name="审核通过"/>
  <endEvent id="rejected" name="审核驳回"/>
</process>
```

### 6.3 流程启动

```java
// 服务者提交入驻申请时启动 BPM 流程
String processInstanceId = bpmProcessInstanceApi.createProcessInstance(
    new BpmProcessInstanceCreateReqDTO()
        .setProcessDefinitionKey("beauty_provider_review")
        .setBusinessKey(provider.getId().toString())
        .setVariables(MapUtil.of(
            "initialReviewer", "admin",
            "finalReviewer", "manager"
        )));

provider.setProcessInstanceId(processInstanceId);
```

### 6.4 任务监听

```java
@Component
public class ProviderReviewTaskListener implements TaskListener {
    
    @Override
    public void notify(DelegateTask delegateTask) {
        String businessKey = delegateTask.getProcessInstance().getBusinessKey();
        Long providerId = Long.valueOf(businessKey);
        
        if ("approved".equals(delegateTask.getTaskDefinitionKey())) {
            // 审核通过
            providerService.approveProvider(providerId);
        } else if ("rejected".equals(delegateTask.getTaskDefinitionKey())) {
            // 审核驳回
            String reason = (String) delegateTask.getVariable("rejectionReason");
            providerService.rejectProvider(providerId, reason);
        }
    }
}
```

### 6.5 回调与状态同步

**BPM 流程结束后回调 beauty 模块**：
- 审核通过 → `beauty_provider.review_status = '通过'`
- 审核驳回 → `beauty_provider.review_status = '驳回'` + 驳回原因

## 7. 重试与熔断策略

### 7.1 API 调用失败重试

**场景**：调用 member、pay、infra 等模块接口失败

**重试策略**：
- 幂等查询操作：最多重试 3 次，间隔 1s
- 非幂等写操作：不重试，直接返回错误

```java
@Retryable(value = RemoteException.class, maxAttempts = 3, backoff = @Backoff(delay = 1000))
public MemberUserRespDTO getUser(Long userId) {
    return memberUserApi.getUser(userId);
}
```

### 7.2 支付回调重试

**场景**：支付回调处理失败（数据库死锁、网络超时等）

**重试机制**：
- pay 模块会自动重试回调
- beauty 模块的回调处理必须**幂等**
- 使用状态条件更新 + 影响行数判断

### 7.3 熔断降级

**场景**：依赖的模块不可用时，避免级联故障

**降级策略**：
- 支付服务不可用 → 禁止下单，提示"支付服务维护中"
- 短信服务不可用 → 只发站内信，不影响核心流程
- 文件上传不可用 → 暂存本地，稍后异步重试

## 8. 事件驱动架构

### 8.1 beauty 模块发布的事件

**订单状态变更事件**：
```java
@Getter
public class ServiceOrderStatusChangeEvent extends ApplicationEvent {
    private final Long orderId;
    private final String beforeStatus;
    private final String afterStatus;
    
    public ServiceOrderStatusChangeEvent(Object source, Long orderId, 
                                          String beforeStatus, String afterStatus) {
        super(source);
        this.orderId = orderId;
        this.beforeStatus = beforeStatus;
        this.afterStatus = afterStatus;
    }
}
```

**监听者**：
- 通知服务：发送站内信和短信
- 结算服务：订单完成后触发结算
- 统计服务：更新服务者接单率、完成率

### 8.2 beauty 模块监听的事件

| 事件 | 来源模块 | 处理逻辑 |
|-----|---------|---------|
| `PayOrderSuccessEvent` | pay | 订单支付成功，更新状态为"待接单" |
| `PayRefundSuccessEvent` | pay | 退款成功，冲正抽成和收入 |
| `MemberUserDisabledEvent` | member | 会员被禁用，关联的服务者自动停止接单 |

## 9. 接入时序图

### 9.1 消费者下单 + 支付流程

```
消费者端 -> beauty:order:create (创建订单，状态"待支付")
         -> pay:order:create (创建支付单)
         <- 返回支付参数
         -> 调起微信/支付宝支付
微信/支付宝 -> pay:callback (支付成功回调)
            -> pay 发布 PayOrderSuccessEvent
            -> beauty:listener (监听事件，更新订单"待接单")
            -> 通知服务者端
```

### 9.2 服务者接单流程

```
服务者端 -> beauty:order:accept (接单)
         -> 分布式锁 beauty:order:accept:{orderId}
         -> 状态条件更新 (待接单 -> 已接单)
         -> 锁定排班时段
         -> 释放锁
         -> 发布 ServiceOrderStatusChangeEvent
         -> 通知消费者端 "服务者已接单"
```

### 9.3 订单完成 + 结算流程

```
服务者端 -> beauty:order:complete (上传服务证据，完成服务)
         -> 订单状态变更为"已完成"
         -> 发布 ServiceOrderStatusChangeEvent
         -> 结算服务监听事件
         -> 创建 beauty_settlement (T+7 待结算)
定时任务 -> SettlementReleaseJob (每天凌晨 3 点)
         -> 查询 T+7 到期的结算单
         -> 更新状态为"可提现"
         -> 更新服务者 available_balance
```

2. **短信签名**：是否使用统一签名，还是单独申请"轻龄到家"签名？
3. **对象存储桶**：是否共用现有桶，还是为美业敏感文件单独创建私有桶？
4. **BPM 审批流**：服务者入驻审核是否需要多级审批（初审 + 复审）？
5. **通知优先级**：订单状态变更时，站内信和短信是否都发，还是只发其一？
6. **定时任务执行时间**：结算释放任务是否需要避开业务高峰期？
7. **熔断降级**：支付服务不可用时，是否允许"先下单后支付"模式？
