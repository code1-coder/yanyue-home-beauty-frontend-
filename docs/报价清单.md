# 轻龄到家 · 产品报价清单

> 本报价基于 [服务产品需求文档（PRD）](服务产品需求文档（PRD）.md)、[原型整体结构](原型整体结构.md)、[共通业务规则与跨端流程](common/业务规则与跨端流程.md) 及三端需求、原型、接口能力清单整理。
>
> 原型阶段与 PRD 优先级不是同一维度：本清单以原型第一/第二/第三阶段作为报价拆分依据，保留 PRD 的 P0/P1/P2 供产品确认。

## 1. 报价口径

### 1.1 终端与工期定义

| 项目 | 口径 |
| --- | --- |
| 消费者端 | 微信小程序，当前工程规划为 HBuilderX + uni-app Vue 3 + uview-plus |
| 服务者端 | 微信小程序，当前工程规划为 HBuilderX + uni-app Vue 3 + uview-plus |
| 管理后台 | Web，当前工程规划为 Vue 3 + Element Plus |
| Web 工期 | 小程序或后台前端的人/天，含页面、交互、状态展示、表单校验、接口联调和基础异常态 |
| Server 工期 | 真实接口、数据模型、业务规则、状态机、权限校验、异步任务、支付/退款/结算回调及日志等后端工作的人/天 |
| 估算精度 | 需求草案阶段估算，建议按 ±30% 作为商务报价浮动范围 |
| 计价粒度 | 每行是一个可独立验收的功能工作包；Server 已按跨端领域复用做合并，不按三端重复建设整套业务底座 |

### 1.2 估算假设与排除项

- 按两个独立微信小程序和一个管理后台 Web 交付；不另计 iOS/Android 原生工程，但原 PRD 的兼容要求仍需产品确认。
- 微信支付、支付宝支付均保留在范围内，按标准 SDK/接口接入估算；不含商户申请、资质审核、渠道排队和第三方服务费。
- 按单城市首发、单语言、无即时通讯、暂不处理发票/保险/税务估算。
- 地图定位/距离、短信、推送、对象存储、图片审核、物流等按标准第三方能力接入估算；不含第三方采购费用和额外合规认证。
- 不含产品经理、项目管理、独立测试团队、视觉设计、运维、云资源、压测、灾备和 7×24 值守专项工期。
- `apps/consumer`、`apps/provider` 的模拟前端可复用页面结构，但模拟 JSON 不代表正式接口已完成；若直接复用现有页面，Web 工期可在确认代码质量后另行下调，Server 工期不因此减少。
- 金额、订单状态、排班冲突、抽成/结算、提现门槛和权限以 Server 为最终裁决，移动端和后台只做展示与操作入口。

## 6. 跨端 Server 复用与计价说明

以下能力按领域只建设一套，后续终端按页面接口、权限和联调增量计入，不重复计完整底座：

| 共用能力 | 首次计入阶段 | 复用范围 |
| --- | --- | --- |
| 用户会话、验证码、文件上传、基础消息投递 | 第一阶段 | 消费者端、服务者端、管理后台 |
| 项目/服务者查询、地理位置与距离计算 | 第一阶段 | 消费者浏览、服务者配置、后台管理 |
| 排班、半小时占用、服务时长、前后缓冲、冲突检测 | 第一阶段 | 消费者预约、服务者排班、后台调度 |
| 服务订单状态机、取消、接单/拒单、服务凭证 | 第一阶段 | 消费者、服务者、后台 |
| 金额试算、优惠分摊、抽成快照、退款抽成冲正 | 第一阶段 | 消费者下单、服务者收益、后台财务 |
| 微信/支付宝支付、退款、异步回调、支付流水 | 第一阶段 | 服务订单及第二阶段商城订单 |
| T+7 结算、可提现余额、提现门槛 >1 元、手续费、打款状态 | 第一阶段 | 服务者收益、后台财务 |
| 优惠券规则 | 第二阶段 | 消费者领用/下单、后台营销 |
| 商城订单、库存、物流、售后 | 第二阶段 | 服务者商城、后台商城 |
| 内容、评论、点赞收藏关系和推荐数据 | 第二/三阶段 | 消费者发现、后台内容、推荐统计 |

> 汇总表中的 Server 501 人天是按这些复用关系调整后的工作包基线，不应再将消费者端、服务者端和后台的同一订单/支付/结算底座分别乘三。若改为多城市、多商户、多支付主体或复杂分账，需重新评估。

## 7. 报价前必须确认的事项

1. **交付平台**：当前工程规划是微信小程序，PRD 同时写有 iOS/Android 兼容；是否追加 App 或 H5 端，需单独确认。
2. **支付与资金**：微信/支付宝主体、退款时限、分账/打款渠道、回调重试、幂等、对账文件和异常人工处理流程。
3. **金额规则**：优惠券在项目金额和上门费之间的分摊规则，退款时平台抽成和服务者收入的冲正规则。
4. **履约规则**：取消规则、拒单是否影响排序、超服务半径提示文案、服务时长与缓冲边界、排班并发锁定策略。
5. **资质与合规**：实名、银行卡/收款账户、证件审核服务、证件到期提醒和自动暂停接单的合规要求。
6. **商城规则**：商品规格、库存并发、物流承运商、收货确认、售后类型和退款责任。
7. **消息渠道**：短信、站内信、订阅消息的模板、触发时机、已读规则和失败重试。
8. **数据与推荐**：统计口径、区域热力、智能推荐是否需要算法服务、埋点平台和数据留存周期。
9. **第三阶段需求**：服务者等级、数据看板、内容互动和推荐策略目前主要来自原型描述，应在开发前补充 PRD。
