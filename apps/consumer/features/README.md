# 业务能力模块规划

> 来源：[消费者需求](../../../docs/consumer/需求.md)、[接口能力清单](../../../docs/consumer/接口清单.md)和[共通规则](../../../docs/common/业务规则与跨端流程.md)。以下为未来模块边界，不是已有源码或接口定义。

按业务能力而非页面文件组织交互、状态及数据访问。候选模块（名称可调整）：

| 候选模块 | 职责 | 边界提示 |
| --- | --- | --- |
| account | 登录、协议、资料、实名认证展示 | 服务端鉴权权威；实名申请 P1。 |
| home / catalog | 首页推荐、分类、项目搜索与详情 | Banner P1；不混入订单最终计算。 |
| beautician | 美容师列表、资质、评价、服务范围 | 资质与接单资格以服务端为准。 |
| booking | 时段、地址选择、试算与确认订单 | 前后缓冲、半小时粒度；超区可下单；并发占用及金额由服务端裁决。 |
| address / location | 地址管理、城市与定位选择 | 定位权限、手选地址和实际服务地址分开。 |
| payment | 支付发起、支付结果查询和展示 | 不凭客户端渠道回跳宣称支付成功。 |
| order | 服务订单、取消、退款/售后、订单动作 | 按服务端状态和可用操作展示，不自行推进状态或计算退款。 |
| review | 服务评价、我的评价 | 服务评价 P0；我的评价与追评 P1。 |
| profile | “我的”聚合入口、设置 | 入口聚合，不复制其他模块的业务规则。 |
| coupon / message / discover / support / safety | 优惠、通知、内容、投诉、安全 | 按需求优先级与原型阶段确认后接入；消息 P0 与阶段二冲突待定。 |

候选名不是必须建立的空模块，不创建模拟接口；拆分与合并以业务边界决定。消费者端不包含服务者工具商城、收益提现或后台审核。跨端金额/订单状态不在前端共享包复制，最终解释权在服务端。未来实现点的注释要求见[骨架设计](../ARCHITECTURE.md)。
