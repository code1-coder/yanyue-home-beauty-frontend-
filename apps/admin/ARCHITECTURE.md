## 目标与边界

- 规划独立 **Vue 3 + Element Plus** Web 后台；以左侧菜单 + 顶部栏承载原型工作台、审核中心、业务、财务、系统等入口。原型的 Element UI 示意是交互参考，不是可直接使用的 Element Plus API。具体版本、构建工具、路由与状态方案在获准建工程后验证。
- 管理者负责审核、配置、业务管控、财务和统计，不替代消费者端下单或服务者端接单。后端框架未确定，Web 不承担身份、数据权限、支付、结算和打款的最终裁决。
- 面向多城市、多项目、多抽成模板演进：薄页面、独立业务能力、应用壳、通用能力、Web 适配分层。配置变更及历史订单快照分开处理，不把当前规则写死在页面、公共表格或菜单中。

## 依赖与可调整边界

建议 app 组合导航与页面 → pages 薄页面 → features 业务能力 → shared / platform；app 只承载登录态展示、布局、菜单与入口组装，不直接落地资金、审核或订单判定。页面负责列表/详情/弹窗组合、筛选参数及导航；业务模块承接状态、交互与未来协议适配。复用仅提取稳定且确有复用的通用能力，不让 shared 形成“万能服务”。业务模块之间通过清晰的公开边界、实体标识与服务端契约协作，不循环依赖另一模块的内部状态。

同一实体可从多个入口操作，但**审核中心、财务管理与服务者/订单详情不得各自实现不同的提现审核、资质审核或退款规则**；入口复用相应业务能力，权限、审计和状态以服务端权威结果为准。服务订单与商城订单使用各自的状态、金额及售后口径，不能仅因为都有“订单”就共享资金判定。角色、菜单和数据权限的配置是后台 P0 能力，但前端隐藏菜单/按钮仅为展示控制，服务端必须逐请求校验。

## 页面与阶段

[pages/README.md](pages/README.md)逐项映射原型 34 行页面清单。原型**没有后台页面路由路径**，其中独立抽成设置等以弹窗示意，系统设置可含多个 Tab；文档不擅自补造 URL、文件名或把每一行强制变成独立路由。原型第一阶段为登录、工作台、审核中心、服务者、项目、订单、抽成、财务、提现；第二阶段为营销、内容、评价、商城；第三阶段为数据统计、系统精细化。PRD 将**角色权限、结算周期/提现规则、优惠分摊规则列为 P0**，即使原型称第三阶段“系统精细化”，首期哪些系统配置必须交付仍需确认；不能据此降级 P0。P1/P2 亦按 PRD 保留。

## 待设计接口与关键流程

[后台接口能力清单](../../docs/admin/接口清单.md)尚非正式契约；URL、方法、请求/响应、错误码、权限矩阵、并发版本、导出、上传、回调均待确认。未来各 features 以正式契约接入，不由页面假定数据字段或凭本地操作推进状态。

1. **审核**：入驻/资质、提现、退款/售后统一通过对应能力处理，展示资料、意见、前后状态和操作结果；通过/驳回及打款须服务端校验权限与当前状态，留痕并通知对应端。资质过期自动暂停接单，Web 不以展示或本地编辑替代审核生效。
2. **订单/排班**：订单列表、详情、退款、改派（P1）与时间池/冲突标记（P1）分开；半小时排班、项目时长及前后缓冲影响占用。超半径订单可下单且美容师可拒单；后台不得擅改规则为自动拦截。改派与退款的可操作状态、冲突和并发处理需服务端契约确定。
3. **抽成与财务**：模板和独立抽成配置不回写历史订单快照；上门费参与抽成，优惠分摊和退款冲正按确认规则执行。服务端负责支付流水、结算单和打款权威状态，结算周期默认 T+7 且可配置；余额严格 **> 1 元** 才可提，手续费与到账金额以服务端核算为准。对账 P1，不能把 UI 显示“已打款”视为支付渠道到账凭证。
4. **商城**：平台自营商品/库存、独立商城订单、物流与售后是 P1；不接入服务订单抽成或美容师接单资格。跨入口查询可以复用展示，但不要混用交易和退款状态机。
5. **系统与运营**：角色/菜单/数据权限 P0、财务规则 P0；其他菜单、城市/距离、操作日志、协议、消息、统计按各自 PRD 优先级和原型阶段规划。城市扩展须避免页面常量和跨城市数据泄露；任何可见数据范围由服务端权限执行。

## 未来实现的就近约束

获准开发后遵守[就近约束](AGENTS.md)和[全仓约定](../../agent.md)：在真正的审核、状态变更、金额展示/计算及权限使用附近写简短注释，说明 PRD 章节、不变量和待确认口径，并配套测试。此设计文档不能代替代码位置的约束；最终状态和资金校验、幂等、操作审计都应在服务端落实，前端只展示与提交有权限的操作。

| 未来边界 | 不得遗漏的约束 |
| --- | --- |
| 审核与资质 | PRD §4.5、§5.3.2：人工审核和证件有效期；过期自动暂停接单；通过/驳回留痕。 |
| 订单、改派、排班 | PRD §4.2、§4.3、§5.3.6–7：半小时与缓冲占用，超区可下单且可拒单；改派 P1，服务端处理冲突。 |
| 抽成模板与服务订单 | PRD §4.1、§5.3.8：独立抽成优先于默认模板，订单创建时保存比例快照；上门费参与抽成，优惠分摊和退款比例冲正。 |
| 结算、提现、退款 | PRD §4.1、§4.4、§5.3.9：默认 T+7 可配置、余额 > 1 元、手续费可配置，审核后打款；支付/退款/到账均由服务端确认并留痕。 |
| 商城订单 | PRD §4.6、§5.3.13：与服务订单独立，不影响接单资格或等级。 |
| 角色/数据权限及财务规则 | PRD §5.3.16：权限、结算/提现及优惠分摊是 P0；菜单隐藏或禁用按钮不构成服务端授权。 |
