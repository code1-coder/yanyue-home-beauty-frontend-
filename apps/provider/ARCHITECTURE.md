# 服务者端架构与联调边界

> 当前已建立独立 uni-app Vue 3 + uview-plus 模拟前端。本文保留早期规划的业务边界；实际源码与运行方式见 [README](README.md)。JSON 和本地存储不是正式接口。
>
> 产品依据：[原始 PRD §3、§4、§5.2、§6、§8.2、§9、§11](../../docs/服务产品需求文档（PRD）.md)与[原始原型 §一、§三、§五、§六、§七](../../docs/原型整体结构.md)。端内索引：[需求](../../docs/provider/需求.md)、[原型](../../docs/provider/原型.md)、[接口能力](../../docs/provider/接口清单.md)、[共通规则](../../docs/common/业务规则与跨端流程.md)。如有差异，以两份原始资料为准；技术方向见[技术选型与仓库结构](../../docs/技术选型与仓库结构.md)。

## 目标与端边界

- 当前优先规划 **HBuilderX + uni-app Vue 3 + uview-plus** 的独立服务者微信小程序工程，不建立 Android/iOS 工程；原始 PRD 的兼容要求并未取消。具体组件兼容组合须在获准建工程后验证。
- 保留原型的工作台 / 订单 / 商城 / 我的四个 TabBar 入口和原型页面语义；建议路由不是现有页面文件或已注册路径。商城为 PRD P1、原型第二阶段，首期 Tab 如何呈现须产品确认，不擅自删除。
- 仅承载美容师登录入驻、资质、工作台、排班、可接项目和定价、服务订单履约、收益提现、独立工具商城、评价消息与个人设置。消费者下单/支付及后台审核/打款不在本端实施。
- 扩展原则是薄页面 + 业务模块 + 端内共享 + 平台适配。城市、项目、抽成模板等变化经服务端契约驱动，不在页面中写死业务规则；不预设跨端运行时共享包。

## 已建立的工程目录

```text
apps/provider/
├── AGENTS.md             # 就近约束
├── README.md             # 端入口
├── ARCHITECTURE.md       # 本方案
├── pages/README.md       # 原型页面映射与导航边界
├── features/README.md    # 按业务能力划分的未来模块
├── shared/README.md      # 端内非业务通用能力
└── platform/README.md    # 微信小程序平台能力适配
```

现有 `pages.json` 注册 27 个页面路径；`features/contracts.ts` 定义前端能力，`features/services.ts` 是唯一数据适配器入口，当前实现位于 `features/mock/services.ts`，种子数据来自 `features/mock/data.json`。正式接口确定后应在适配层映射鉴权、DTO、错误、分页、文件上传与支付状态查询。

## 当前核查结果

- 页面与导航：27 个页面路径已注册，拒单弹窗作为组件实现；工作台、订单、商城、我的 4 个底部 Tab 已保留。
- 能力与数据：接口清单的 18 行能力均已映射到 `ProviderServices` 的本地模拟方法，JSON 种子数据覆盖登录入驻、工作台、排班、项目、服务订单、收益提现、收款账户、个人资料、消息、商城和评价。
- 验证：`npm run typecheck` 通过；`npm test` 通过，1 个测试文件共 10 项测试通过；`npm run build:mp-weixin` 构建成功；`npm run build:h5` 构建成功并已发布浏览器预览。
- 交付边界：小程序构建目录为 `dist/build/mp-weixin`；H5 预览为 [服务者端预览](https://h5-six-sigma.vercel.app)。上述构建和预览只证明本地模拟前端可运行，不代表真实接口、真机兼容或审核发布已完成。

依赖方向建议：pages → features → shared / platform；页面仅负责路由、展示组合和页面参数，业务模块拥有交互状态与未来数据访问边界；shared 不承载抽成、资格、占用或提现业务判定。模块之间用明确公开边界、稳定标识和服务端契约协作，不直接依赖其他模块的页面或内部状态。鉴权、订单状态、排班占用、结算/提现与支付最终以服务端权威结果为准。

## 页面与阶段

[pages/README.md](pages/README.md)逐项对应原型的 28 行清单（包括一项拒单弹窗组件），不把弹窗虚构为页面路由。原型第一阶段为登录、入驻、工作台、排班、订单、收益、提现、我的；第二阶段为商城、评价、消息；第三阶段为数据看板、等级。PRD 将**消息列为 P0**，而原型放在第二阶段；商城、评价为 P1。优先级不是交付阶段，首期消息范围及商城 Tab 呈现须确认，不得直接更改 P0/P1 或新增已确认页面。

原型 `/pages/...` 是建议路由；未来如采用分包，应先验证 TabBar 主包、跳转及目标平台限制，不能为了分包改变原型入口。三端保持独立工程，服务者端不与消费者端合包。

## 未来接口边界与交互

[接口能力清单](../../docs/provider/接口清单.md)只是能力盘点，尚无 URL、方法、字段、鉴权、错误码、分页、上传、支付回调或版本约定。未来按 features 模块收口数据访问，不让页面假定后端字段、枚举与操作权限；不在此阶段编造接口。

1. **入驻与资格**：登录 → 提交实名/证件/主体资料 → 后台人工审核 → 查询状态或驳回原因 → 通过后配置服务范围、项目、排班并接单。证件过期自动暂停接单；客户端只能展示服务端资格与可操作项，不能凭本地证件日期或页面状态授予接单资格。
2. **排班与接单**：半小时段、请假/暂停、前后缓冲、服务时长和已有占用影响候选时段；批量设置/复制为 P1。接单开关和接/拒单动作需服务端重新校验资格、占用与订单状态，并将结果同步消费者端。超服务半径的订单仍可创建，美容师可拒单，不在客户端以距离强制拦截。
3. **履约**：订单列表/详情 → 接单或带原因拒单 → 开始 → 完成及服务凭证上传；实际操作顺序与完成条件以正式契约和原型流转确认，不把本地操作成功直接视为订单终态。导航/联系用户为 P1，敏感信息与平台权限另行确认。
4. **收益与提现**：服务订单创建时抽成比例快照，上门费参与抽成，退款按规则冲正；客户端只展示权威的余额、待结算、明细和服务端试算。默认 T+7 可配置；**余额 > 1 元** 才可申请提现，手续费和到账金额经服务端确认，后台审核后打款，回跳或本地提交不等于已到账。
5. **商城独立链路**：平台自营商品 → 独立商城订单 → 支付 → 物流/售后；与服务订单、抽成/结算和接单资格隔离。支付结果以服务端核验为准，不凭小程序支付回调断定成功。

## 未来实现的就近约束

获准编码后按[就近约束](AGENTS.md)与[全仓约定](../../agent.md)，在实际判定、提交或金额展示附近写简短约束注释，标明原始 PRD 章节和未确认口径，并补充相应测试；本设计文档不能代替实现处的注释。客户端展示性校验不替代服务端并发、幂等和权限控制。

| 未来边界 | 必须保留的约束 |
| --- | --- |
| 入驻、资质与接单开关 | PRD §4.5、§5.2.1：人工审核，证件过期自动暂停接单；客户端不得自批或本地恢复资格。 |
| 排班、缓冲、请假和订单动作 | PRD §4.2、§5.2.3、§5.2.5：半小时粒度；前缓冲 + 项目服务时长 + 后缓冲；冲突和接单资格由服务端最终校验。 |
| 服务半径、上门费与拒单 | PRD §4.3：超区可下单且美容师可拒单；上门费按固定/阶梯/满免设置并参与平台抽成。 |
| 收益、结算与提现 | PRD §4.1、§4.4：抽成比例订单创建时快照、优惠分摊和退款冲正；默认 T+7 可配置；余额严格 **> 1 元** 才可提现，平台审核后打款。 |
| 商城订单及支付 | PRD §4.6、§5.2.7：商城订单独立于服务订单，不影响接单资格/等级；支付结论由服务端确认。 |
| 订单状态和服务凭证 | PRD §5.2.5、§6：只显示服务端允许的动作；凭证上传、重复操作及状态流转遵守正式契约，不在客户端自行推进。 |

## 待确认后才落地

- HBuilderX/CLI 工程模式、依赖版本与锁定方式、uview-plus 兼容性、微信小程序分包/提审及证件与图片上传权限。
- 原型商城 Tab 与第二阶段安排、消息 P0 与第二阶段安排；等级/数据看板仅在原型第三阶段提及，不以骨架补造已确认页面或功能。
- 正式接口契约：身份与资质有效性、订单可操作动作和幂等、排班版本/冲突、文件上传、金额/手续费试算、商城支付查询、消息通知与错误处理。
- 原始 PRD 的 iOS/Android 兼容范围和微信/支付宝支付 P0 与当前微信小程序工程路线如何协同交付；骨架不裁剪原始需求。
- 优惠分摊、退款冲正、拒单是否影响排序、超区提示、提现手续费/到账及对账细则，需要产品与技术负责人确认。

确认后再同步相应需求、原型摘录与接口能力文档；当前可运行应用仅为模拟前端，不代表真实支付、审核和结算能力。
