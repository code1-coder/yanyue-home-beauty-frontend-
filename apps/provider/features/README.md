# 业务能力模块规划

> 来源：[服务者端需求](../../../docs/provider/需求.md)、[原型](../../../docs/provider/原型.md)、[接口能力清单](../../../docs/provider/接口清单.md)和[共通规则](../../../docs/common/业务规则与跨端流程.md)。下列为能力划分；当前实现已由各模块、`contracts.ts`、`services.ts` 和 `mock/` 覆盖，数据仍为本地 JSON 模拟。

未来按业务能力收口交互状态与数据访问，不以每个页面复制一套业务规则。模块可随正式接口契约拆分/合并，页面只依赖对外边界：

| 候选模块 | 对应能力与需求优先级 | 边界约束 |
| --- | --- | --- |
| account / onboarding | 手机验证码登录、入驻申请、审核状态与重提 P0 | 实名、健康证、美容师证、个体户信息敏感；人工审核和资质有效性以服务端为准。 |
| qualification / profile | 资质列表/到期、个人资料 P0；设置 P1 | 审核记录与禁用不可由资料页修改成通过。 |
| workbench | 接单开关、数据概览、待办和快捷入口 P0 | 聚合服务端状态，不维护另一个订单/收益真相源。 |
| schedule | 半小时排班、缓冲、请假/暂停 P0；批量、复制 P1 | 已占用段不能编辑为可约；并发冲突和接单资格以服务端结果为准。 |
| project / service-setting | 平台项目、可接配置与定价 P0；服务半径和上门费规则 P0 | 上门费参与抽成；超半径不在客户端强制拦单。 |
| service-order / fulfillment | 列表、详情、接拒单、开始/完成、凭证 P0；导航/电话 P1 | 服务订单状态和可用操作服务端权威；拒单原因与凭证上传契约待定。 |
| income / withdrawal / payout-account | 收益明细、提现、提现记录、收款账户 P0 | 抽成快照、退款冲正及手续费不由本端计算为最终值；余额 > 1 元，后台审核后打款。 |
| mall | 商品、商城独立订单、支付、物流、售后 P1 | 不复用服务订单状态与抽成结算；商品购买不影响接单资格或等级。 |
| review / message | 评价查看/回复/申诉 P1；订单/审核/提现/系统消息 P0 | 消息原型第二阶段，与 PRD P0 的交付冲突待确认。 |

## 当前实现核查

| 项目 | 结果 |
| --- | --- |
| 能力分组 | `auth`、`onboarding`、`workbench`、`schedule`、`projects`、`orders`、`finance`、`profile`、`messages`、`mall`、`reviews` 共 11 组 |
| 接口清单覆盖 | 18 行能力均有 `ProviderServices` 方法和 JSON 模拟实现 |
| 测试 | `features/mock/services.test.ts` 共 10 项测试通过 |
| 联调边界 | 仅完成本地模拟；正式 HTTP 契约、鉴权、错误、分页、上传、支付回调和服务端权威状态仍待确认 |

服务订单与商城订单各有独立类型和模拟状态；正式 HTTP 契约尚未确认。实现注释与测试边界见[架构说明](../ARCHITECTURE.md)。
