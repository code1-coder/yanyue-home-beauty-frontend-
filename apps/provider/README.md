# 服务者端

> 当前状态：独立 uni-app Vue 3 + uview-plus 微信小程序**模拟前端**。本次核查已确认 27 个小程序页面路径、4 个底部 Tab、拒单弹窗和接口清单中的 18 项能力均有前端入口及 JSON 模拟适配器；无后端、正式 HTTP 契约、真实支付/审核/结算能力。数据来自 `features/mock/data.json`，本地演示变更写入 uni storage。原始产品范围未裁剪。

按[原始 PRD](../../docs/服务产品需求文档（PRD）.md)保留业务范围；本次已批准采用 **HBuilderX + uni-app Vue 3 + uview-plus**，当前优先规划独立微信小程序工程，原始产品范围不因此删减。职责限于美容师入驻资质、服务设置、排班接单、履约、收益提现及独立工具商城；跨端业务状态与金额规则见[共通规则](../../docs/common/业务规则与跨端流程.md)。

三端技术方向与目录约定见[技术选型与仓库结构](../../docs/技术选型与仓库结构.md)。本端依赖版本由 `package.json` 和 `package-lock.json` 固定。

## 运行与验证

在本目录执行 `npm ci`，再运行 `npm run dev:mp-weixin` 或 `npm run build:mp-weixin`；将 `dist/dev/mp-weixin` 或 `dist/build/mp-weixin` 导入微信开发者工具。H5 预览可运行 `npm run dev:h5` 或 `npm run build:h5`。质量检查为 `npm run typecheck`、`npm test`、`npm run build:mp-weixin`。本次核查结果：`vue-tsc --noEmit` 通过，`vitest` 10/10 通过，微信小程序构建成功。未配置真实小程序 appid（manifest 使用游客 appid），真机与 HBuilderX 尚未验证。

演示初始为已审核的测试服务者；登录页接受任意格式正确的 11 位手机号和 6 位数字验证码，不发短信。设置页可重置演示数据。请勿输入真实身份证、银行卡或个人资料。微信小程序端选图仅保存到小程序本地文件并记录路径（重置演示数据时清理），不上传服务器；卸载/清理应用后不可恢复，也不可作为跨设备凭证。H5 辅助预览仍使用临时文件路径。

**验收以微信小程序为准**：运行 `npm run typecheck`、`npm test`、`npm run build:mp-weixin`，将 `dist/build/mp-weixin` 作为小程序项目导入微信开发者工具，逐页检查 27 条注册路径、四个 Tab 及 JSON 演示流程。`manifest.json` 的 `mp-weixin.appid` 应由项目维护者核对与验收账号一致；构建成功不等于真机、开发者工具或审核发布验收通过。H5 仅用于辅助预览。

## 能力与联调边界

`features/contracts.ts` 的 `ProviderServices` 是**前端能力契约**，`features/services.ts` 是唯一适配器入口，当前指向 `features/mock/services.ts`。页面通过它读写状态。正式 API 确认后，在该边界替换实现、映射 DTO 与错误/权限/分页/上传/回调规则，页面无需推测 HTTP URL 或请求字段。

| 接口清单能力 | 前端适配器 |
| --- | --- |
| 登录、入驻提交（含演示收款账户）、审核状态/资质更新 | `auth`、`onboarding` |
| 工作台汇总、接单开关 | `workbench` |
| 半小时排班、缓冲、请假/暂停、批量与复制 | `schedule` |
| 平台项目、可接配置和定价 | `projects` |
| 服务订单列表/详情、接拒单、开始、凭证与完成 | `orders` |
| 收益、提现试算/申请/记录、收款账户 | `finance` |
| 个人资料、服务范围和上门费 | `profile` |
| 消息列表/详情 | `messages` |
| 商品/规格/库存、独立商城订单/支付/物流查询/售后 | `mall` |
| 评价列表/回复/申诉 | `reviews` |

原型 27 个页面路径均在 `pages.json` 注册；拒单是 `features/orders/RejectDialog.vue`。消息详情、物流及售后在列表/商城订单详情中呈现，原型未列独立路由。商城支付是本地状态演示，不唤起支付 SDK；微信/支付宝实际渠道仍待产品和技术确认。资质审核、并发占用、超区提示、优惠分摊、手续费、退款冲正、接单权限和提现打款均需服务端权威接口。演示的静态金额及历史明细不因本地订单动作而自动结算。

接口能力清单共 18 行，当前每项都有前端页面入口和 `ProviderServices` 模拟方法，覆盖测试位于 `features/mock/services.test.ts`。入驻只保存演示用账户标识；排班复制以选中日期为首日复制连续七天；本地请假拒绝覆盖已接单占用；模拟支付后商品库存递减，物流仍取自 JSON/本地状态。这些模拟行为不定义正式接口的字段、URL、鉴权或业务状态机。逐项核查结论见[接口能力清单](../../docs/provider/接口清单.md)。

**联调待办**：确定 18 项能力的 HTTP 契约与错误/分页模型；接入真实会话及页面访问控制、短信验证码、实名和凭证上传（当前仅临时路径）、审核结果、订单并发占用和消费者同步、支付回调及物流、手续费/结算/退款冲正、提现审核打款。现有演示登录只改变本地标志，页面访问尚不作为认证或权限保障；真实接入前必须补齐服务端授权与前端会话路由处理。模拟手机号、凭证路径和账户标识不得用于生产数据。
